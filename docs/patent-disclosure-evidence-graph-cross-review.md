# 技术交底书：基于多源异构文档的证据图交叉审核方法

> 起草日期：2026-07-30
> 状态：初稿
> 建议申请类型：发明专利

---

## 一、技术领域

本发明属于计算机辅助审核与自然语言处理交叉领域，具体涉及一种将多份异构格式文档（电子表格、文字处理文档、PDF、ZIP 归档包）统一转换为结构化证据图，并通过图推理实现跨文档自动交叉审核的方法。

---

## 二、背景技术

### 2.1 现有技术方案

目前检测报告审核主要依赖人工或简单的规则比对：

1. **人工审核**：审核人员逐份比对委托单、测试计划、原始记录和检测报告，效率低、易遗漏。
2. **规则引擎审核**：预先编写固定字段比对规则（如报告编号一致性），只能覆盖有限的结构化字段。
3. **单一 LLM 审核**：将文档全文提交大语言模型做端到端判断，缺乏可追溯的证据链，结论不可复现。

### 2.2 现有技术缺点

1. **文档异构性未解决**：四份必需文档格式各异（.xls 委托单、.xlsx 测试计划、.docx 检测报告、.zip 原始记录），包含表格、扫描件、图表和自由文本，缺乏统一的表示方法。
2. **证据不可追溯**：现有 AI 审核方案给出最终结论但无法回指原文，人工无法验证。
3. **跨文档关系缺失**：测试计划定义的应做项目、原始记录证明的实际执行、检测报告发布的最终结果之间存在隐含的对应关系，现有技术无法显式建模和校验。
4. **缺失与未提取混淆**：现有方案无法区分"报告确实没有填写"和"AI 未成功提取"，导致误报率过高。
5. **跨文档命名不一致**：同一测试项在计划、记录和报告中可能使用不同名称（如"电源线瞬态传导抗扰 P2a"与"脉冲 2a"），缺乏系统性的身份消歧方法。

## 三、发明内容

### 3.1 技术问题

如何将多源异构格式文档自动转换为统一的、可追溯的、支持关系推理的证据图，并基于该图执行跨文档自动交叉审核。

### 3.2 技术方案概述

本发明的核心是一种**双层证据图架构**：

- **公共定义图**（Definition Graph）：存储可跨文档集复用的标准知识、测试定义、别名映射和质量门禁规则，以不可变发布快照形式版本化。
- **文档集运行图**（Run Graph）：按文档集独立存储本次四份文档的提取事实、关系推理和审核结论，禁止跨文档集自动共享执行事实。

整体流程分为五个阶段：

```
阶段 1: 文档单元化
  异构文档 → 原生文本 + 渲染图像 → 双通道文档单元

阶段 2: 结构化证据提取
  文档单元 → 确定性提取/AI 提取 → 结构化观察 → 证据记录

阶段 3: 证据图构建
  观察 + 关系推理 → 节点(entity) + 边(relation) + 声明(claim)

阶段 4: 多维度交叉检查
  图中节点/边/声明 → 24 项通用检查 → 审核发现(finding)

阶段 5: 人工裁决
  finding + 证据链 → 人工确认/驳回/重审 → 最终结论
```

### 3.3 关键技术特征

#### 特征 1：异构文档的双通道单元化

对于每种文档格式采用专门的处理策略，同时提取**原生文本通道**和**视觉渲染通道**：

| 文档格式 | 原生文本提取 | 视觉渲染 |
|---------|------------|---------|
| .pdf | PyMuPDF 逐页提取文本 | 2x 缩放渲染为 PNG，生成 data URL |
| .docx | python-docx 提取段落+表格文本 | LibreOffice 转 PDF 后渲染 |
| .xlsx/.xls | openpyxl/xlrd 提取所有单元格值 | LibreOffice 转 PDF 后渲染（xlsx 自动适配列宽和横向打印） |
| .zip | 递归解压并逐文件处理 | 同上 |

每个文档单元（DocumentUnit）同时携带 `native_text` 和 `image_data_urls`，系统根据内容特征自动判定视觉提取需求类型（`visual_reason`）：

- `none`：纯文本足够
- `scan`：扫描件，必须视觉提取
- `complex_table`：表格密集，需同时使用文本和视觉通道
- `targeted_recovery`：定向补证，针对特定区域追加视觉提取

#### 特征 2：确定性+AI 混合多阶段提取

AI 提取前先执行零成本确定性提取：

- **TOC 提取**：纯正则表达式，三种策略回退（经典点线目录 → 虚拟标题目录 → 裸编号抽取），将检测报告按测试项自动切分为独立段落。
- **订单格式提取**：基于已知模板坐标映射的 openpyxl 确定性解析，产生结构化 `OrderFormData`，无需 AI token。

AI 提取采用**多 pass 分层策略**，每 pass 独立 schema、独立 token 预算：

- Pass 1 结构化：封面信息 + 样品描述 + 结果汇总表
- Pass 2 仪器：全部仪器清单（无上限）
- Pass 3 逐项数据：按 TOC 切分的段落独立提取，包含限值表、测试过程、数据行

提取结果经代码级校验（余量公式 margin = limit - result、背景噪声、量级一致性），未通过门禁的局部内容保持 `partial` 状态。

#### 特征 3：LLM 分任务策略矩阵

将 LLM 调用按认知负荷分为 5 种任务类型，每种独立配置模型、推理模式和门禁：

| 任务类型 | 认知负荷 | 模型策略 | 推理模式 | 质量门禁 |
|---------|---------|---------|---------|---------|
| `fast_transcription` | 低 | 轻量模型 | 关闭推理 | 代码清点行数校验 |
| `structured_extraction` | 中 | 高性能模型 | 关闭推理 | 完整 JSON + 数量一致性 |
| `classification` | 低 | 轻量模型 | 关闭推理 | 结果必须在候选集内 |
| `semantic_audit` | 高 | 高性能模型 | 开启推理 high | 证据可回指原文 |
| `knowledge_reasoning` | 极高 | 高性能模型 | 开启推理 high | 原文逐字证据，人工确认后发布 |

Prompt 采用稳定前缀策略：静态角色、规则和 JSON schema 放在 system prompt，动态文档内容放在 user prompt，以充分利用大模型的自动上下文缓存。

#### 特征 4：证据图的节点和关系体系

定义了 15 种节点类型和 17 种关系类型的形式化体系：

**节点类型**：

| 节点 | 语义 | 示例 |
|------|------|------|
| `test_definition` | 公共测试定义 | "电压瞬态发射 — 脉冲 A" |
| `test_requirement` | 本次计划要求 | 测试计划中声明的应做项目 |
| `test_execution` | 一次执行实例 | 某样品在某模式下某轮次的执行 |
| `document_observation` | 文档观察 | 报告第 6 页表格中提取的 "Startup feature: Pass" |
| `claim` | 可追溯声明 | 某参数的归一化值、原始值、单位和来源证据 |
| `instrument` | 仪器设备 | 接收机、天线、LISN 的名称/型号/编号 |
| `person_role` | 人员角色 | 主检/审核/批准人及其签署状态 |
| `standard_clause` | 标准条款 | 已发布标准快照中的某一条款 |
| `evidence_artifact` | 证据制品 | 波形截图、测试布置照片 |
| `anomaly_observation` | 异常观察 | 测试中出现的啸叫、重启等异常 |
| `review_finding` | 审核发现 | 最终输出的确定问题/通过/提醒/未决 |

**关键关系类型**：`required_by`（计划要求→执行）、`executed_as`（执行→文档观察）、`has_claim`（观察→声明）、`covers`（执行→覆盖维度）、`contradicts`（跨来源冲突）、`summarizes`（聚合汇总）。

所有参与审核比对的参数和结果均保存为独立 `claim` 节点，同时记录原始值、归一化值、单位、来源证据 ID、提取方式、模型版本、置信度和人工确认状态。

#### 特征 5：证据门禁与未决保持机制

系统定义了三级证据状态：

- `confirmed_pass`：证据充分，审核通过
- `confirmed_error`：证据充分，确认存在错误
- `unresolved`：证据不足，保持未决

**关键规则：缺失升级为确认错误必须完成五步门禁**：

1. 文件和目标区域覆盖证明
2. 别名与父子关系扩展检索
3. 相邻节点、表头、目录和候选页面检索
4. 局部视觉补证（定向 Qwen VL 提取）
5. 二阶段独立复核未找到反证

任何一步未通过，结论保持 `unresolved`。这从根本上解决了"AI 没找到"和"报告没填写"的混淆问题。

#### 特征 6：跨文档测试项身份消歧

按优先级递减的六层判定链解决命名不一致：

1. 已发布公共定义图中的显式结构
2. 明确编号和标准结构匹配
3. 独立参数/结果证明其可独立执行
4. DeepSeek 提出带原文证据的候选关系
5. 程序校验证据存在性和图约束合法性
6. 独立证据或第二阶段反驳式复核

仍不明确则保持 `unresolved`，不得强行合并。

样品（sample_id）、模式（mode）、执行轮次（execution_round）三级隔离，确保不同条件下的同名测试不被错误合并。

#### 特征 7：结构化提取复用机制

对于委托单和测试计划等结构化良好的文档，确定性提取结果经过人工或自动审核后，在同一文档版本不变的条件下，后续审核运行可直接复用已审核的结构化数据（`structured_authority`），跳过 AI 提取，在保证质量的前提下显著降低计算成本。

#### 特征 8：启动恢复与后台任务容错

文档提取、标准知识构建、知识图谱构建三类后台任务均基于逻辑 key 去重（如 `document-extraction:{doc_id}`）。服务重启时自动扫描数据库中处于 `pending`/`extracting` 状态的任务并恢复执行。文件原始内容丢失时，以明确错误信息标记失败而非静默丢弃。

## 五、权利要求建议

### 独立权利要求 1（方法）

一种基于多源异构文档的证据图交叉审核方法，其特征在于，包括以下步骤：

(a) 获取至少两份异构格式的文档，所述文档包括电子表格格式的第一文档、文字处理格式的第二文档和便携式文档格式的第三文档；

(b) 对各文档执行双通道单元化处理，提取原生文本内容并渲染为页面图像，生成同时包含文本数据和图像数据的文档单元；

(c) 对文档单元执行混合提取，包括确定性规则提取和/或基于大语言模型的语义提取，生成结构化观察结果和可定位的证据记录；

(d) 基于所述观察结果和证据记录构建文档集运行图，所述运行图包含节点和边，所述节点至少包括需求节点、执行节点、观察节点和声明节点，所述边表示节点间的逻辑关系；

(e) 在所述运行图上执行多项检查，每项检查根据图中节点的属性和关系进行判定，生成具有稳定标识符和关联证据链的审核发现；

(f) 当所述审核发现涉及缺失判定时，在完成目标区域覆盖验证、别名扩展检索、定向视觉补证和独立复核之前，将所述审核发现的状态保持为未决（unresolved）。

### 从属权利要求 2

根据权利要求 1 所述的方法，其特征在于，步骤 (b) 中对不同格式的文档采用不同的单元化策略：对 .pdf 文档使用 PyMuPDF 逐页提取文本并渲染；对 Office 文档先提取原生结构化文本，再通过文档转换工具生成 PDF 后渲染；对 .zip 归档文件递归解压后逐文件处理，并对每个文档单元自动判定视觉提取需求类型。

### 从属权利要求 3

根据权利要求 1 所述的方法，其特征在于，步骤 (c) 中的混合提取采用多 pass 分层策略：先执行零 AI token 消耗的确定性提取（包括基于正则表达式的目录提取和基于模板坐标映射的订单格式提取），再按结构层、仪器层和逐项数据层分别执行大语言模型提取，每层使用独立的输出 schema 和 token 预算。

### 从属权利要求 4

根据权利要求 1 所述的方法，其特征在于，步骤 (c) 中大语言模型的调用按认知负荷分为至少三种任务类型，不同类型的调用独立配置模型规格、推理模式和输出质量门禁：转录型任务使用轻量模型且关闭推理；抽取型任务使用高性能模型且关闭推理；语义审核型任务使用高性能模型且开启推理。

### 从属权利要求 5

根据权利要求 1 所述的方法，其特征在于，所述运行图与一公共定义图配合构成双层图架构，所述公共定义图以不可变发布快照形式存储跨文档集复用的标准知识和测试定义，历史运行固定引用当时的发布快照；所述运行图按文档集独立隔离，禁止跨文档集自动共享执行事实。

### 从属权利要求 6（系统）

一种基于多源异构文档的证据图交叉审核系统，其特征在于，包括：文档单元化模块、证据提取模块、图构建与推理模块、多维度检查模块和人工裁决模块，用于执行权利要求 1 至 5 中任一项所述的方法。

### 从属权利要求 7（存储介质）

一种计算机可读存储介质，其上存储有计算机程序，该程序被处理器执行时实现权利要求 1 至 5 中任一项所述的方法。

## 六、技术效果

1. **证据可追溯**：每个审核发现均关联精确到页面/行/单元格的证据 ID 和原文引用，人工可验证。
2. **低误报率**：通过五步门禁机制区分"未提取"与"真缺失"，避免将提取不完整升级为确认错误。
3. **跨格式统一**：将 .xls、.xlsx、.docx、.pdf、.zip 五种异构格式统一为双通道文档单元，屏蔽底层格式差异。
4. **计算成本可控**：确定性提取零 AI token 消耗，结构化复用避免重复 AI 调用，多模型分任务策略使轻量任务不消耗高性能模型配额。
5. **可迭代改进**：检查具有稳定 check_id，新检查可增量添加；历史结论保留完整证据链和模型版本，支持变更追溯。

## 七、与现有技术的区别

| 对比维度 | 现有规则引擎 | 现有 LLM 端到端 | 本发明 |
|---------|------------|---------------|--------|
| 文档格式支持 | 仅结构化字段 | 仅纯文本 | 五种异构格式，双通道（文本+视觉） |
| 证据可追溯 | 无 | 无（黑盒输出） | 每个 finding 附带证据 ID 和原文引用 |
| 缺失 vs 未提取 | 无法区分 | 无法区分 | 五步门禁，未完成保持 unresolved |
| 跨文档关系 | 无 | 隐式 | 15 种节点 × 17 种关系显式建模 |
| 身份消歧 | 精确字符串匹配 | LLM 自由联想 | 六层判定链 + 三级隔离 |
| 知识复用 | 无 | 无 | 公共定义图发布快照 + 结构化权威复用 |
| 计算成本 | 低（但覆盖窄） | 高（全文重复提交） | 分层策略，确定性零 token + 缓存友好 |

## 八、具体实施方式示例

### 示例 1：EMC 检测报告四文档交叉审核

**输入文档**：
1. 委托单（.xls）：EMC测试申请表，包含申请单位、样品名称/型号、额定参数、测试要求
2. 测试计划（.xlsx）：试验大纲，包含测试项目列表、执行条件、判定标准
3. 原始记录（.zip）：包含多个 PDF 文件的压缩包，每个 PDF 对应一个测试项目的原始测量数据和环境记录
4. 检测报告（.docx）：最终报告，包含封面、样品信息、结果汇总表、逐项检测数据和仪器清单

**处理过程**：

S1 — 文档单元化：
- 委托单 .xls → `_xls_native_text()` 提取 82KB 单元格文本 → LibreOffice 转 PDF 渲染为页面图像
- 测试计划 .xlsx → `_xlsx_native_text()` 提取 1120KB 文本 → LibreOffice 转 PDF 渲染
- 原始记录 .zip → 解压出多个 PDF → 逐 PDF 单元化（文本 + 图像）
- 检测报告 .docx → `_docx_native_text()` 提取 1556KB 文本 → LibreOffice 转 PDF 渲染

S2 — 证据提取：
- 委托单：确定性 `OrderFormExtractor` 解析模板坐标，产生 `{applicant: {...}, product: {...}, test_requirements: {...}}`
- 测试计划：DeepSeek 提取三层（基本信息 + 测试项目 + 逐项细则）
- 原始记录：确定性 PDF 表格解析 + DeepSeek 富化
- 检测报告：Pass 0 确定性 TOC（发现 9 个测试项及页码范围）→ Pass 1 结构化 → Pass 2 仪器 → Pass 3 逐项数据

S3 — 图构建：对每个测试项建立 `test_requirement → test_execution → document_observation → claim` 证据链，跨文档关系（如计划声明"Startup feature"对应报告汇总表第 6 页的"Startup feature: Pass"）

S4 — 交叉检查：执行 24 项通用检查，产生 findings（如 RESULT-EMPTY-001: 6 个聚合测试项的明细待验证，保持 unresolved）

S5 — 人工裁决：审核人员在 UI 中查看每个 finding 的证据链（原文引用 + 页面定位），逐项确认/驳回。

### 示例 2：环境检测报告三文档审核（扩展场景）

同样适用于委托单 + 采样记录 + 检测报告的三文档交叉审核，仅需调整 `_REQUIRED_DOC_TYPES` 配置和文档类型特定的确定性提取器。

## 九、附录：当前系统实现的 24 项检查目录

### 核心一致性（5 项）
| check_id | 检查内容 |
|---------|---------|
| GRAPH-COVERAGE-001 | 计划要求、原始执行和报告发布的项目覆盖 |
| GRAPH-IDENTITY-001 | 测试项身份、别名和父子关系 |
| GRAPH-CLAIM-001 | 参数、结果和执行状态的跨来源一致性 |
| GRAPH-SAMPLE-001 | 样品、型号、模式和轮次覆盖 |
| GRAPH-CONCLUSION-001 | 汇总结论与明细结果一致性 |

### 文档内部结构（8 项）
| check_id | 检查内容 |
|---------|---------|
| DOC-STRUCTURE-001 | 章节/项目编号重复、同号异名、目录与正文不一致 |
| DOC-STRUCTURE-002 | 项目总数与实际节点数不一致 |
| DOC-TIMELINE-001 | 单项日期落在报告声明检测区间内 |
| DOC-TIMELINE-002 | 签发日期不早于最后执行日期 |
| DOC-TIMELINE-003 | 样品接收日期不晚于试验开始日期 |
| DOC-REFERENCE-001 | 标准编号、版本和条款引用规范化 |
| DOC-SIGNATURE-001 | 主检/审核/批准签署完整性 |
| DOC-PLAN-REF-001 | 报告引用的计划编号与计划自身编号一致 |

### 要求、结果与覆盖维度（8 项）
| check_id | 检查内容 |
|---------|---------|
| RESULT-DIMENSION-001 | 多条件要求是否逐项给出结果 |
| RESULT-TYPE-001 | 结果值、单位和量纲是否符合要求类型 |
| RESULT-EMPTY-001 | 明细结果为空但汇总宣称通过 |
| RESULT-DUPLICATE-001 | 互斥测试或不同条件间疑似复制粘贴 |
| RESULT-FORMULA-001 | 同一证据行中读值、修正量、结果和余量重新计算 |
| RESULT-LIMIT-001 | 结果与同一适用行的明确限值比较 |
| COVERAGE-MATRIX-001 | 型号、样品、温度、模式、点位等覆盖矩阵缺口 |
| EVIDENCE-PROFILE-001 | 测试类型要求的波形、照片、量化值等证据是否具备 |

### 其他（3 项）
| check_id | 检查内容 |
|---------|---------|
| DOC-CROSS-FIELD-001 | 跨文档字段一致性（客户名称、样品型号、额定参数等） |
| INSTRUMENT-IDENTITY-001 | 仪器名称/型号/编号一致性 |
| INSTRUMENT-CAL-001 | 仪器校准有效期覆盖 |
| SEMANTIC-VARIABLE-001 | 开放参数的语义归类与跨文档比对 |
| ANOMALY-CONCLUSION-001 | 异常观察与最终结论的一致性 |
| STANDARD-SCOPE-ADVISORY-001 | 标准强制要求但计划遗漏的提示 |
