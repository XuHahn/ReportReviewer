# 标准库与审核知识检索整改计划

> 状态：三期已实施（不可变发布版本、双语要求、BGE-M3 混合检索、人工映射与引用门禁）；金标数据持续积累。

## 目标

将当前文档集中的“测试标准”临时上传位改造成可复用的标准库选择能力。标准文件只需入库和知识化一次，后续文档集选择已有标准即可；审核时根据测试计划、原始记录和检测报告中的标准引用，检索对应标准条款并连同原文证据交给 LLM 判断。

## 当前差距

- `emc_standards` 仅保存编号、版本及人工录入条款 JSON，不保存原文件、文件指纹、解析状态和知识块。
- 文档集里的 `test_standard` 只是一个可选上传文件，只提取全文，不进入标准库。
- 一个文档集目前只能表现为一个标准文件，无法关联多个已有标准。
- 审核调用没有标准检索步骤，LLM 只能看到四份业务文档，无法引用上传标准的具体章节。
- 现有 C11 只能根据报告自身描述猜测“标准合规”，不具备可靠的标准原文依据。

## 总体架构

### 1. 标准资产层

扩展标准主表，保存：

- 规范化标准编号、名称、发布机构、版本/年份、状态；
- 原文件名、文件内容、SHA-256 文件指纹、页数；
- 解析状态、知识化状态、失败原因、创建人与更新时间；
- 唯一约束：规范化标准编号 + 版本；文件指纹用于阻止重复上传。

增加文档集与标准的多对多关联表，使一套报告可以选择多个标准，并记录选择人、选择时间和是否由文档引用自动建议。

### 2. 标准知识化层

标准上传后异步执行一次知识化：

1. 提取 PDF/DOCX 原文并保留页码。
2. 识别章节树、标题、正文、表格、注释、适用范围和交叉引用。
3. 按页面边界组成有界知识块，保留标准编号、版本、章节、起止页码和原文，不跨页丢失证据。
4. 用 LLM JSON Output 抽取标准编号、版本、名称、发布机构和类别；审核时对相关知识块按模块做语义重排与要求理解。
5. 任何标准相关结论都必须指回标准编号、版本、知识块 ID、章节、页码和原文。

当前检索采用 SQLite 证据库 + 本地 BGE-M3 多语言向量 + 词法候选 + LLM 复核。SQLite 保存 float32 向量用于开发机；部署到服务器时由相同接口切换 PostgreSQL + pgvector。没有足够检索支持或 LLM 无法确认时禁止随机回退，生成“需人工映射”问题。

### 3. 上传审核 UX

将上传页第五个“测试标准”文件卡改为“选择测试标准”：

- 支持搜索标准编号、名称和版本；
- 支持一次选择多个标准；
- 展示知识化状态、版本、页数和更新时间；
- 搜不到时提示用户前往“标准库”上传；审核页本身不上传或知识化标准；
- 检测到相同编号+版本或相同文件指纹时，直接提示选择已有标准，不重复建库；
- 文档解析完成后，根据四份文档中出现的标准引用给出“建议关联”列表，由用户确认，不静默替换已选标准。

标准库页面改为文件驱动：上传标准、查看解析进度、查看章节、查看原文证据、重试知识化、停用旧版本。原有手工新增条款作为高级编辑能力保留，但不再是主要入口。

### 4. 审核检索与判断

审核启动时先生成“标准引用清单”：

- 从计划、记录、报告提取标准编号、版本、章节号和相关测试项；
- 与文档集已选标准做精确匹配；
- 有章节号时精确取章节并补充父级、子级和关联表格；
- 无章节号时，以测试项名称、测试目的、参数和标准编号在该标准内检索候选章节，再由 LLM 重排；
- 不允许跨版本、跨标准库模糊借用条款。

标准上下文按测试模块注入报告驱动审核：

- 测试计划决定需要执行的测试项目全集；
- 标准解释适用范围、测试方法、测试条件、参数、等级、限值和判定规则；
- 原始记录证明实际执行；
- 检测报告证明最终披露和结论。

比较底层语义，不比较字面是否重复。例如“脉冲4”应展开为标准中的波形参数，再与计划、记录和报告参数比较。只有底层参数冲突、适用范围错误、判定规则错误或引用了错误版本/章节时才报问题。

### 5. 问题模型、证据与日志

新增标准相关问题类型：

- `standard_version_mismatch`：引用版本与所选版本不一致；
- `standard_clause_unresolved`：无法唯一定位引用章节；
- `standard_requirement_conflict`：计划/记录/报告与标准要求冲突；
- `standard_applicability_conflict`：测试项或等级不在条款适用范围内。

每条问题必须展示：引用来源原文、标准编号与版本、标准章节与页码、标准原文、业务文档执行/声明原文、LLM 的结构化比较结果。

新增结构化日志事件：

- `standard_upload_started/completed/duplicate/rejected`；
- `standard_knowledge_build_started/completed/failed`；
- `standard_reference_extracted`；
- `standard_retrieval`（查询、候选章节、命中分数、最终章节）；
- `standard_context_injected`（模块、块 ID、字符数）；
- `standard_validation_decision`（判定、证据 ID、置信度）；
- `standard_retrieval_unresolved`。

日志不记录整段标准原文，只记录标准 ID、章节、页码、块 ID 和长度，避免日志泄漏及体积失控。

## 实施顺序

1. 数据库迁移、模型和标准文件 CRUD，加入去重、版本与状态。
2. 标准解析、OCR、分页知识块、LLM JSON 编目和 FTS5 索引。
3. 文档集关联标准 API，并兼容已有 `test_standard` 上传记录的迁移。
4. 上传页标准选择器及标准库文件化管理界面。
5. 标准引用抽取、检索、模块上下文构建及缓存。
6. 接入报告驱动审核与 C11，禁止无标准证据的标准合规结论。
7. 问题证据展示、Excel 导出和操作日志（沿用通用问题来源结构）。
8. 单元测试、API 测试、前端类型检查和真实数据集回归。

## 验收标准

- 同一标准文件不会被重复存储或重复知识化。
- 一个文档集可选择多个已有标准，也可新增后自动选择。
- LLM 的标准合规结论必须带可定位的标准原文证据。
- 不因简称与展开参数写法不同而误报；底层参数冲突必须报出。
- 标准缺失、版本不符、章节无法定位时不得由 LLM 凭常识补齐。
- 历史四文档文档集在未选择标准时仍可打开；审核行为按最终确认的缺失标准策略执行。

## 已确认规则

1. 标准不是必选项；文档集允许选择零个或多个标准，企业标准与国际、国家、行业标准同等入库。
2. 同一标准编号的不同版本并存，历史审核始终绑定当时选择的版本；相同文件指纹不重复入库。
3. 未选择任何标准时允许继续审核，只跳过标准条款、适用范围、参数和限值相关判断，并在选择卡、提交确认和审核结果中明确提醒用户。
4. 未选择标准不能被判定为“标准通过”；四份业务文档之间的一致性审核仍正常执行。
5. 只有原文知识化状态为 `ready` 且结构化要求状态为 `published` 的标准才能在审核页选择；LLM 提取完成不等于可用于正式审核。
6. 只写标准编号、未写章节号时，允许系统结合测试项语义自动检索章节；标准问题必须带知识块 ID 和原文页码证据。

## 真实数据验收（HC_E202605287495）

- `ISO 7637-2 2011 .pdf` 为 48 页纯扫描 PDF，直接文本长度为 0，已验证自动进入 OCR 回退。
- 48/48 页提取出文本，约 5.6 万字符，形成 16 个带页码知识块；DeepSeek JSON 编目识别为 `ISO 7637-2:2011`。
- 使用中文“系统12V电源电压波动试验 / 脉冲4”检索，语义重排召回第 16–22 页证据；第 20 页原文明确说明本版已移除测试脉冲 4、5a、5b。
- DeepSeek JSON Output 两次返回空 content 后第三次重试成功；日志确认本地 FTS 候选与重试兜底均生效，空响应不会被视为“标准没有要求”。

## 第二阶段：可审核的关系型知识图谱（2026-07-15）

### 已确认的治理规则

1. LLM 从 PDF 提取的每条标准要求必须经过人工确认，未经确认不能进入报告审核。
2. 人工确认采用细粒度逐条审核，分别核对适用范围、测试方法、测试条件、参数限值、仪器要求、判定规则和引用关系。
3. 审核人员可以修改提取内容后确认；系统永久保存修改前值、修改后值、人员、时间和备注。
4. 排除无效内容必须填写原因。已发布要求发生任何修改后，标准自动退回待发布状态。

### 数据模型

保留 `standard_knowledge_chunks` 作为不可替代的原文证据层，在其上建立可迁移到 PostgreSQL 的关系型逻辑图谱：

- `standard_graph_clauses`：标准版本内的条款、父条款、页码和来源知识块；
- `standard_graph_requirements`：要求类型、测试项目、自然语言陈述、适用条件、逐字证据、置信度和人工状态；
- `standard_requirement_parameters`：参数名称、符号、比较符、值/区间、单位和原始写法；
- `standard_requirement_relations`：引用、适用、依赖、替代等关系；
- `standard_requirement_revisions`：人工修改与确认的不可覆盖审计快照。

当前使用 SQLite 实现，表结构没有依赖 SQLite 专有 JSON 查询，后续可迁移 PostgreSQL。只有跨标准版本影响分析、引用网络遍历成为性能瓶颈时，再将已发布关系同步到 Neo4j；Neo4j 不作为权威数据源。

### 生命周期与发布门禁

```text
上传 PDF
→ 原文/OCR/分页知识块 ready
→ 结构化提取 extracting
→ 证据与完整性代码校验
→ pending_review
→ 人工逐条确认/修改/排除
→ published
→ 报告审核可选择
```

发布必须同时满足：所有提取单元成功、待确认数量为 0、至少存在一条已确认要求。标准可不选择；未选择时仍按既定规则跳过标准相关审核并提示用户。

### 抽取可靠性与日志结论

- 原来的 4,500 字符知识块可能使 DeepSeek 输出在 JSON 闭合前截断，因此结构化抽取改为页内约 1,200 字符的有界单元，最终按条款与逐字证据去重。
- 每条 `evidence_quote` 必须经过规范化后在所属原文单元中反查，页码必须位于来源页；无法反查、空陈述和越界证据直接拒绝。
- 正文出现 `shall/must/required/necessary/applicable/indispensable` 等规范性措辞但模型返回空数组时，自动进行针对性复核；仍为空则记录为未覆盖单元并禁止发布。
- 封面、目录、前言和版权页在代码识别后跳过，避免将出版声明误识别为测试要求。
- OpenAI/httpx 底层日志级别限制为 WARNING；项目日志只记录模型输出长度与 SHA-256 摘要，不记录标准原文或模型返回正文。

### 面向非技术人员的确认工作台

- 左侧按章节展示自然语言要求和待确认状态；
- 中间使用业务字段编辑测试项目、要求类型、要求内容、适用条件和参数；
- 右侧同时展示逐字证据和定位到对应页的 PDF；
- 操作只有“确认并保存”“不是有效要求”“发布到审核系统”，不展示 JSON、数据库 ID 或知识块编号；
- 顶部显示整体进度，全部处理完成前禁用发布按钮。

### 真实结构化抽取验收（2026-07-15）

- ISO 7637-2:2011 的 48 页 OCR 原文被切分为 69 个正文提取单元，另有 5 个封面/目录/版权单元被代码跳过。
- 首轮完成 68/69 个单元；第 28 页包含多张 OCR 畸变表格，DeepSeek 连续返回空内容或截断 JSON，系统保留已得到的 192 条候选并阻止发布。
- 增加失败单元增量恢复：只重试失败页，不清空已提取数据、人工状态或修订历史；同一整页再次失败后自动切为不超过约 600 字符的页内片段提取并合并去重。
- 第 28 页恢复成功后达到 69/69 个单元、60 个章节片段、200 条候选要求、0 个失败单元，其中 2 条低置信度规范性候选必须人工判断。
- 同一条款跨页或跨片段时，确认工作台按“条款号 + 标题”合并左侧导航；每条要求仍保留自身页码、逐字证据和来源块。
- 实际调用发布接口返回 `409：仍有 200 条要求待确认`，验证未经逐条人工确认的标准不会进入报告审核。

## 第三阶段：工业化发布、双语证据与混合检索（2026-07-16）

### 不可变知识版本

- 标准 PDF 文件版本以 SHA-256 固定；每次人工确认后发布为不可变 `R1/R2/...` 知识版本。
- 文档集不再只保存标准 ID，而是保存当时选择的发布版本 ID。后续重建标准草稿或发布 R2，不会改变历史审核使用的 R1。
- 发布快照保存条款、参数、关系、人工确认人、Prompt 版本及向量模型版本；只有向量索引成功后才进入 `published`。

### 双语要求与人工治理

- `original_statement` 保存标准原文中的完整规范性要求，不允许人工改写。
- `interpretation_zh` 保存 LLM 中文释义草稿，必须经标准审核员逐条确认。
- 审核上下文同时注入原文、中文释义、页码和发布版本；最终问题证据以原文为准，中文只用于解释。
- 增加 `standard_reviewer` 角色；管理员兼具该权限，普通报告审核员只在审核页选择已发布标准。

### 检索与拒答门禁

1. 人工映射优先，可标记“对应要求”或“标准不覆盖”。
2. 无人工映射时，BGE-M3 与词法检索分别生成候选。
3. DeepSeek 只在候选集合内复核，且候选必须具备词法或向量支持。
4. 同一标准内部引用只展开一层；跨标准引用不会自动启用其他标准。
5. 无高置信度结果时生成 `S03 标准知识定位核对`，不得取任意前几条，也不得判为标准通过。

### 引用标准提交门禁

- 四份文件正文中显式出现的 ISO、IEC、CISPR、EN、GB、QC/T、SAE、DIN、FCC、企业 `Q/` 标准编号会形成引用清单。
- 引用项必须选择对应已发布版本，或由用户逐项填写本次跳过原因；未处理的引用会阻止锁定提交。
- 跳过原因、选择版本和操作人均进入审计记录。

### 人工映射范围

- `set`：仅当前文档集；
- `project`：指定项目组；
- `standard`：所有使用该发布版本的审核。

映射与发布版本绑定，升级到新知识版本后必须重新确认，避免旧版本语义被静默继承。
项目组选择会写入 `document_sets.project_group_id`，审核检索按当前文档集、项目组、标准全局的顺序使用人工映射，不依赖前端临时状态。
