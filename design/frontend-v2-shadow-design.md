# 前端影子版本 V2 设计说明

状态：已实现影子版本，目录为 `frontend-v2/`。

## 产品判断

审核员的核心任务不是浏览统计，而是对机器发现逐条形成有依据的人工结论。信息架构因此采用全局顶部导航；任务内部使用连续五步流程；问题裁决阶段把页面宽度优先留给原图证据。

核心视觉对象是“四文档证据轨道”：委托单、试验计划、原始记录和检测报告在每条问题上分别显示已定位、冲突、缺失或未参与。同一文件同一页的证据合并为一个页签，并在原页同时绘制多个编号框：红色表示冲突或错误、琥珀色表示待人工确认、青绿色表示一致或通过、蓝色表示要求或参照。框号与页下原文摘录一一对应。

## 技术选型

- React 19 + TypeScript + Vite 8
- React Router 7：独立路由和角色入口
- TanStack Query：请求缓存、失效和轮询
- Mantine 9：弹窗、输入、通知、主题与无障碍基础
- Recharts：仪表盘趋势和问题分布，按路由懒加载
- react-dropzone：四资料槽位上传
- 自定义可调整证据分栏：避免额外 PDF 渲染层

证据页通过向后兼容的 `/evidence/{evidence_id}/preview` 生成；影子版额外传递同页证据 ID 和受限的语义色类型，由后端在原始 PDF/Office 页面上统一定位、绘制并输出 PNG，不在浏览器重新解释 PDF 坐标。归档内证据只合并同一个成员文件的同一页，避免跨文件误框。

## 响应式策略

- 1920px：问题队列、原图证据、裁决详情三栏同时显示。
- 980–1250px：问题队列收进任务抽屉，原图和裁决详情并排。
- 720px 以下：原图与裁决详情纵向排列，仍保留全屏证据查看。

## 与现有后端的边界

现有任务终态为 `reviewed`，没有 `archived` 状态。影子版遵循真实状态机，不伪造归档写入。若以后需要区分“审核完成”和“正式归档”，应另行设计数据库状态迁移、权限、审计日志和历史任务兼容策略。
