# 本地视觉模型与测试计划提取决策（2026-08-03）

## 结论

当前开发机为 Apple M3 Pro（12 核、18GB 统一内存）。本项目采用：

- 视觉转录：`mlx-community/Qwen3-VL-8B-Instruct-4bit`，12K KV，单页单请求；
- 任意版式测试计划语义提取：DeepSeek 文本模型双遍清点；
- 代码：只负责物理分页、扫描页路由、JSON/Pydantic 校验、原文回查、数量门禁与跨页合并，不按固定表头或坐标提取业务含义。

## 候选比较

| 候选 | 官方能力 | 本机适配判断 | 结论 |
|---|---|---|---|
| Qwen3-VL 8B Instruct | 原生 256K 上下文，强调文档、空间定位和多语言视觉理解 | MLX 已有 4-bit 权重；8B 在 18GB 上可保留足够的页面图像和 12K KV 空间 | 采用 |
| Gemma 3 12B IT | 128K 上下文、多模态、140+ 语言 | 4-bit 权重更大，许可证需单独接受；本项目中文工业表格没有现成回归优势 | 暂不采用 |
| InternVL 3.5 8B | 多模态推理与动态视觉分辨率 | 当前项目的 MLX/OpenAI 兼容服务路径没有同等成熟的已验证配置 | 作为后续离线对照，不作为默认 |

## 为什么测试计划不能交给固定规则

测试计划可能表现为封面、目录、总表、跨页表格、段落和逐项章节的任意组合。固定列名、列号、页码或模板坐标都会把某一厂商样式误当成业务定义。现行流程因此分为：

1. 给所有原生文本加“文件第 N 页”边界；原生文本不足的页才交给视觉模型逐字转录。
2. 文本 LLM 首遍提取完整三层结构；第二遍独立重做测试项目清点。
3. 两遍结果按明确项目身份合并，不使用无约束模糊匹配。
4. 每个项目和细则必须携带连续原文与文件位置；代码逐字回查，回查失败即标记提取不完整。
5. 下游覆盖检查按文件内测试项目身份匹配，不按文件名或父子项位置绑定。

## 运行边界

- 视觉模型只做页面转录和定位，不直接决定审核结论。
- 文本 LLM 做跨页语义理解，但输出必须经过结构、原文和数量门禁。
- 18GB 配置不加载 12B 以上模型与超大 KV，避免统一内存压力使整套审核吞吐下降。
- 任何模型升级必须使用固定真实页集评估项目召回、字段原文命中、定位命中和单页延迟后再替换默认值。
