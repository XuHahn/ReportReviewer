标准库知识化与审核技术架构

标准入库一次、结构化一次；每次审核只检索相关章节，并保留完整证据链。

A. 标准资产层
标准文件上传PDF / DOCX，计算 SHA-256
编号与版本去重相同编号+版本或相同指纹直接复用
版本并存历史审核始终绑定原标准版本
›
B. 知识化与检索层
版面与章节解析页码、章节树、正文、表格、注释
LLM JSON 条款抽取适用范围、方法、参数、限值、判定
FTS5 + 精确索引 + LLM 重排标准编号/章节优先，不跨版本借用
›
C. 报告驱动审核层
标准引用解析从计划、记录、报告提取编号与章节
模块化上下文注入业务原文 + 命中条款 + 页码证据
参数级一致性判断简称展开，比较要求/执行/声明/结论

标准库维护与一次审核的运行时链路

标准库上传并知识化
审核页选择已有标准
解析引用并检索章节
随模块送入 LLM
生成带证据问题
为什么不整本送入 LLM

避免上下文溢出、错章节干扰和高成本。每个测试模块只获得命中的章节、父子条款及关联表格。

为什么先不用外部向量库

标准编号和章节具有强结构。SQLite FTS5、章节索引和 LLM 重排足以支撑首版，也更方便部署与追溯。

如何阻止模型臆测

标准类结论必须引用知识块 ID、页码和原文；未命中或存在多个候选时只能标记证据不足，不能判定通过。
