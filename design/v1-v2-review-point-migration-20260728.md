# V1/V2 审查点向统一证据图迁移台账

日期：2026-07-28  
状态：现行设计与实现基线

## 1. 迁移原则

迁移对象是业务审查点，不是 V1/V2 的代码、字段循环、模糊匹配、提示词或严重级别。

每个旧审查点必须重新经过以下链路：

1. 测试计划或明确文档角色证明本次适用；
2. 图中的测试项、样品、模式、轮次或字段角色完成身份对齐；
3. 每个参与判断的值都有可定位原文证据；
4. 数学、集合、日期和精确字符串由确定性规则判断；
5. 语义身份只允许 LLM 提议并经过反证复核；
6. “未提取到”只有在系统/人工覆盖证明后才能升级为“缺失”；
7. 无法闭合的检查保留为 `unresolved`，不得伪装成通过或错误。

## 2. V1 审查点迁移

| V1 审查点 | 统一系统处置 | 新 check_id / 说明 |
|---|---|---|
| 计划、记录、报告测试项覆盖 | 重新实现 | `GRAPH-COVERAGE-001/002`；001 从计划要求检查执行与发布，002 将记录和报告中的正向项目反查完整计划范围；名称别名走证据关系，汇总标题不另算测试项 |
| 目录三方覆盖、目录完整性 | 合并 | 目录只作为报告发布范围的一种结构证据，归入 `GRAPH-COVERAGE-001` / `DOC-STRUCTURE-002`，不另建第二套项目身份 |
| 原始记录不合格结论、报告与记录结论 | 重新实现 | `GRAPH-CONCLUSION-001`；只比较已对齐执行实例的明确结论 |
| 仪器校准有效期 | 重新实现 | `INSTRUMENT-CAL-001`；设备身份、执行日期、校准截止日三者均需证据 |
| 仪器清单交叉比对 | 重新实现 | `INSTRUMENT-IDENTITY-001`；缺项必须先证明清单区域完整，不能把没抽到当缺失 |
| 基本信息、额定电压、零件号 | 重新实现 | `DOC-CROSS-FIELD-001`；只比较相同业务角色的人工确认结构化事实 |
| 日期跨度、签发日期 | 拆分重构 | `DOC-TIMELINE-001/002/003`；执行区间、签发不早于最后试验、接收不晚于试验开始 |
| 测试模式、方法、参数一致性 | 纳入声明图 | `GRAPH-CLAIM-001`；必须先有同一执行实例关系，不允许按相似名称直接比较 |
| 数据行数 | 重新实现 | `DOC-STRUCTURE-002`、`RESULT-DIMENSION-001`；只有系统/人工覆盖证明后才能确认缺行 |
| 四文档多数投票 | 淘汰 | 权威性不能由票数决定；改为按委托单、计划、记录、报告的职责比较 |
| 企业字段格式正则 | 淘汰 | 当前业务边界明确不做企业字段格式合法性检查 |
| 无来源物理范围 | 淘汰 | 只有计划或已发布标准提供明确阈值时才能生成范围检查 |
| 结果、修正量、余量公式 | 重新实现 | `RESULT-FORMULA-001`；模型只转录同一行单元格，图规则重新计算 |
| 明确限值超限 | 重新实现 | `RESULT-LIMIT-001`；限值与结果必须来自同一适用行并有原文证据 |
| 总体结论与单项结果 | 重新实现 | `GRAPH-CONCLUSION-001`；同一 `conclusion_group` 才比较 |
| 封面完整性 | 收紧重构 | `DOC-REQUIRED-FIELD-001`、`DOC-SIGNATURE-001`；仅对明确占位符或经视觉证明的空签署区判错 |
| LLM 深度审核 | 淘汰原流程 | LLM 改为关系/适用性候选与局部补证，不直接写确定错误 |
| 供应商名称 | 角色化迁移 | 只有图中已确认“委托方/供应商/制造商”角色关系后才比较；禁止继续把申请方默认当供应商 |
| 样品数量 | 重新实现 | `GRAPH-SAMPLE-001`；计划声明数与报告明确列出的不同样品 ID 比较，默认提醒人工确认 |
| 测试计划编号 | 重新实现 | `DOC-PLAN-REF-001`；计划自身编号与报告明确引用编号精确比较 |

V1 报告内部 C03/C05/C07 的处置：

- C03 公式与超限分别迁入 `RESULT-FORMULA-001`、`RESULT-LIMIT-001`；
- C05“背景噪声至少低 6 dB”不作为全局常量迁移，只有计划或已发布标准明确给出该要求时才生成阈值声明；
- C07 性能等级不沿用固定 A-E 排序。等级顺序必须来自计划、已发布标准或人工确认的等级定义，再由 `GRAPH-CLAIM-001` / `GRAPH-CONCLUSION-001` 判断。

## 3. V2 审查点迁移

对旧 V2 运行制品的复核显示：112 条比较中有 65 条被标为确定差异，但大量只是把某字段拿到不适用文档中检查“是否出现”，例如要求试验计划、原始记录同时包含委托方地址。这类结果不迁移。

| V2 能力/问题 | 统一系统处置 |
|---|---|
| 事实、证据、比较分层 | 迁移为图节点、证据记录、关系和 finding |
| 原文无法定位门禁 | 保留并加强；无原文证据不产生确定结论 |
| 数量门禁、JSON/schema 门禁 | 保留；失败使运行保持 `machine_incomplete` |
| 文档角色不确定 | 迁移为关系未决，不再跨所有文档强行比较 |
| 标准未选择提示 | 保留；跳过标准条款检查并产生明确提示 |
| 标准生效日不晚于试验日 | 保留审查点；仅在已发布标准版本有明确生效日期时执行 |
| 接收日期不晚于试验日期 | 重新实现为 `DOC-TIMELINE-003` |
| 全字段 presence/absence | 淘汰；只对有适用边和覆盖证明的字段执行 |
| 多数文档值一致即为真 | 淘汰；改为来源职责和实体关系 |
| 无约束模糊名称匹配 | 淘汰；改为编号、定义图、证据 LLM 提议和反证复核 |

## 4. 外部厂商报告经验迁移

外部检查报告提供的是审查模式样本，不保存厂商专用规则：

| 经验类别 | 通用能力 |
|---|---|
| 产品名、零件号、计划编号不一致 | 角色化跨文档声明比较 |
| 章节编号重复、声明数量不等 | `DOC-STRUCTURE-001/002` |
| 日期超范围、接收/签发顺序错误 | `DOC-TIMELINE-001/002/003` |
| 设备编号复用、校准过期 | `INSTRUMENT-IDENTITY-001`、`INSTRUMENT-CAL-001` |
| 要求多条件但结果少条件 | `RESULT-DIMENSION-001` |
| 汇总通过但明细空 | `RESULT-EMPTY-001`，缺失需视觉覆盖证明 |
| 电阻/电容量纲混淆 | `RESULT-TYPE-001` |
| 计算、余量、限值错误 | `RESULT-FORMULA-001`、`RESULT-LIMIT-001` |
| 不同模式数据完全相同 | `RESULT-DUPLICATE-001`，默认提醒而非判错 |
| 波形、照片、量化证据不足 | `EVIDENCE-PROFILE-001`，由测试类型/计划定义证据档案 |
| 变量或名称疑似错写 | `SEMANTIC-VARIABLE-001`，默认提醒 |
| 异常现象但结论通过 | `ANOMALY-CONCLUSION-001`；只有明确违反判据才升级错误 |

## 5. 防回归约束

- 模型输出中的覆盖完成标志会被剥离；只有 `source=system|human` 的覆盖证明可把缺失升级为错误。
- 原生页面“提取完成”不等于某个结果区域“缺失已证明”。
- 供应商与申请方、制造商不得默认视为同一角色。
- 标准只提供要求与理由，不自动扩大计划的必做范围。
- 每个新增检查必须有稳定 check_id、证据、去重键、严重级别和单元测试。
