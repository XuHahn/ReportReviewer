# EMC 报告审核系统 · Shadow V2

独立的前端影子版本。它不会替换或导入 `frontend/`，可与现有界面并行运行。

## 启动

```bash
cd frontend-v2
npm install
npm run dev
```

- 影子版开发地址：`http://127.0.0.1:5174`
- `/api` 默认代理到：`http://127.0.0.1:8000`
- 登录页可进入完整演示模式；也可以直接访问 `/?demo=1`

## 验证

```bash
npm run build
```

## 设计原则

- 视觉方向：精密检测工作台，浅色为主并完整支持深色模式。
- 视觉签名：四文档证据轨道贯穿上传、核查、裁决与完成页。
- 原文优先：裁决工作台先展示后端生成的高亮原图；同页多证据合并展示，以红、琥珀、青绿和蓝色编号框区分错误、待确认、一致与参照，再展示结构化解释和处理动作。
- 状态诚实：资料缺失、系统未完成和无适用输入不会显示成审核通过。
- 角色默认入口：审核员进入工作概览；标准审核员进入标准工作；管理员使用同一应用管理全部功能。

## 主要路由

| 路由 | 功能 |
|---|---|
| `/` | 工作概览、待处理队列、趋势和常见问题 |
| `/tasks` | 审核任务搜索与筛选 |
| `/tasks/:setId/intake` | 四资料上传、标准和项目组范围 |
| `/tasks/:setId/extraction` | 原文与提取字段并排核查 |
| `/tasks/:setId/run` | 证据图审核运行与检查状态 |
| `/tasks/:setId/findings` | 原图高亮、结构化对比与人工裁决 |
| `/tasks/:setId/complete` | 导出、修订和完成状态 |
| `/standards` | 标准知识化、要求确认和发布 |
| `/groups` | 项目组管理 |
| `/users` | 用户和角色管理 |
| `/operations` | 系统设置、运行日志和标签 |

## 后端状态说明

当前后端状态流以 `reviewed` 为终态，没有独立的 `archived` 状态。影子版因此把完成页呈现为“审核完成与导出”，不会向不存在的 `archived` 状态发起写入。
